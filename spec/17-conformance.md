# ShareNet 2.0 — Conformance Framework

**Status:** Normative. This document defines the conformance framework:
golden vectors, architecture regression tests, executable guards against
forbidden pipelines, and per-phase exit conditions.

The keywords "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT",
"SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this
document are to be interpreted as described in RFC 2119.

## 1. Golden Vectors

Golden vectors are canonical byte fixtures that fix the output of a
deterministic function. A conformance test compares the
implementation's output against the vector; deviation fails the build.

### 1.1 Required Vector Sets

| Vector Set                              | Location                              | Inputs                                  | Outputs                                                        |
|-----------------------------------------|---------------------------------------|-----------------------------------------|----------------------------------------------------------------|
| NodeId derivation                       | `conformance/vectors/identity/*.json` | Ed25519 public key bytes.               | `NodeId` text (`node:…`).                                      |
| Canonical CBOR encoding                 | `conformance/vectors/encoding/*.json`| Logical CBOR objects (advertisement, hint, route, proof). | Canonical byte string.                       |
| Advertisement signature                 | `conformance/vectors/advertisement/*.json` | Advertisement object + Ed25519 private key. | Ed25519 signature bytes.                              |
| Route commitment root                   | `conformance/vectors/routing/*.json`  | RouteProposal + RouteAcceptance[].      | 32-byte commitment root.                                       |
| CircuitId derivation                   | `conformance/vectors/circuit/*.json`  | 32-byte route commitment root.          | `CircuitId` text (`circuit:…`).                                |
| Gateway agreement hashes                | `conformance/vectors/gateway/*.json`  | GatewayServiceAgreement fields.         | BLAKE2b-256 digest.                                            |
| Manifest Merkle root                    | `conformance/vectors/content/*.json` | Chunk hash list.                        | 32-byte Merkle root.                                            |

### 1.2 Avalanche Vectors

Each set MUST include at least one vector pair `(input, input')` where
`input'` differs from `input` by a single bit. The corresponding
outputs MUST differ in at least 50% of output bytes for hash-derived
quantities (NodeId, commitment root, Merkle root). This verifies that
the implementation is not accidentally using a weak or non-avalanche
hash.

### 1.3 Cross-Implementation Vectors

Vectors are generated once, stored in JSON, and checked into the
repository. They MUST NOT be regenerated by the implementation at test
time; the test loads the JSON and compares. Regeneration is only
permitted when the spec version bumps and a new vector is added to the
set.

## 2. Architecture Regression Tests

The following ten tests are the **first** architecture regression tests.
They MUST pass at every commit. A failing test blocks merge.

| # | Test Name                                  | What It Verifies                                                                                  |
|---|--------------------------------------------|---------------------------------------------------------------------------------------------------|
| 1 | `node_id_derivation_matches_vector`        | `canonicalNodeIdText(pk)` equals the golden vector for `pk`.                                       |
| 2 | `node_id_invariant_holds`                  | For a generated keypair, `node_id == canonicalNodeIdText(pk)`.                                   |
| 3 | `advertisement_canonical_reencode_equal`   | Re-encoding a received advertisement canonically is byte-equal to received bytes.                  |
| 4 | `advertisement_signature_verifies`         | Advertisement signatures verify for golden vectors.                                              |
| 5 | `advertisement_rejected_on_seq_floor_violation` | A replayed advertisement with `sequence ≤ floor` is rejected, even after prior expiry.    |
| 6 | `link_state_machine_transitions_valid`     | Link state transitions follow the §4 table in `spec/04-links.md`.                                 |
| 7 | `remote_node_hint_promotion_forbidden`     | No code path accepts a `RemoteNodeHint` and returns an `AuthenticatedNodeRecord` without a Link handshake. |
| 8 | `route_proposal_not_a_route`               | A `RouteProposal` is not usable as a `CommittedRoute`; circuit construction from a proposal fails.|
| 9 | `circuit_id_bound_to_route_commitment`      | `CircuitId` changes if any `RouteAcceptance` in the commitment changes.                           |
| 10 | `gateway_blocks_private_address_egress`   | Gateway egress to `127.0.0.1`, `10.0.0.0/8`, `fc00::/7`, etc., is rejected.                      |

## 3. Executable Architecture Guards (Forbidden Pipelines)

The following pipelines are **forbidden**. The conformance suite MUST
include an executable test for each that fails the build if the
pipeline is permitted by any code path.

### 3.1 `TopologyGraph → Dijkstra → Route`

Forbidden. Replaces a multi-phase pipeline (Discovery → Destination
Authentication → Next-Hop Discovery → Path Validation → Service
Negotiation → Route Proposal → Route Acceptance → Committed Route)
with a single graph operation. Test: the conformance suite includes a
topology graph fixture; the routing layer MUST NOT return a route
derived purely from the graph without the participant-acceptance step.

### 3.2 `RemoteNodeHint → AuthenticatedNodeRecord`

Forbidden. There MUST be no function in the reference implementation
whose type signature accepts a `RemoteNodeHint` and returns an
`AuthenticatedNodeRecord`. Test: static type check on the reference
implementation's public exports; runtime check that calling any
function that accepts a `RemoteNodeHint` does not produce an
`AuthenticatedNodeRecord`.

### 3.3 `RemoteNodeHint[] → Circuit` and `RouteProposal → Circuit`

Forbidden. A circuit MUST be constructed only from a `CommittedRoute`.
Test: the circuit module's public API accepts only a `CommittedRoute`;
passing anything else is a compile-time error in TypeScript, and a
runtime throw.

### 3.4 Signature Domain Reuse

Forbidden. The register of domain-separation strings in
`spec/14-security.md` §4 is closed. Test: a static check scans the
reference implementation for all domain string literals and asserts
that each appears in exactly one location and matches exactly one use
in the register.

### 3.5 Custody Violation in the External Crypto Bridge

Forbidden. ShareNet software MUST NOT request, store, or transmit a
user's private key; MUST NOT sign on behalf of the user; MUST NOT
broadcast on behalf of the user. Test: a static scan of the bridge
module's source code for forbidden patterns (`PrivateKey`, `signTx`,
`broadcast`, etc.); a runtime test that exercises the bridge flow and
verifies that no ShareNet component ever holds a private key.

### 3.6 Platform Adapter Semantic Violation

Forbidden. A platform adapter MUST NOT introduce new protocol
semantics. Test: a static check that the platform adapter modules
import only the reference implementation's public exports and do not
define new wire formats, signature domains, or protocol objects.

### 3.7 Self-Reported Contribution Crediting

Forbidden. Civic Points MUST NOT be issued on the basis of a node's
self-reported byte count. Test: the ledger module's `credit` function
MUST accept only a verified `ContributionProof`; passing a
self-reported value fails type check.

### 3.8 Expiration Resets Sequence Floor

Forbidden. Expiration of a prior object MUST NOT lower the sequence
floor. Test: the sequence floor store is queried after an object's
expiry; the floor MUST remain at its prior high-water mark.

### 3.9 Gateway Egress Without Authorization

Forbidden. A gateway MUST NOT forward traffic without a
`GatewayServiceAgreement`. Test: the gateway module's egress function
MUST refuse a request that lacks a valid agreement.

### 3.10 Authentication-Free Link Usage

Forbidden. A Link in state other than `LINK_UP` MUST NOT be used as a
routing next-hop. Test: the routing module rejects Links not in
`LINK_UP`.

## 4. Phase Exit Conditions

Each phase has an exit condition. The phase is complete only when its
exit condition passes a conformance test.

| Phase | Exit Condition                                                                                                | Conformance Test                                                 |
|-------|---------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------|
| 0     | Spec + ADR merged.                                                                                             | Manual review.                                                   |
| 1     | Crypto primitives pass golden vectors.                                                                         | `crypto/golden.test.ts`.                                         |
| 2     | NodeId derivation passes golden vectors; invariant holds.                                                       | `identity/golden.test.ts`, `identity/invariant.test.ts`.         |
| 3     | NodeAdvertisement canonical form + verification pass.                                                           | `advertisement/golden.test.ts`, `advertisement/verify.test.ts`.  |
| 4     | Link handshake brings peer from `LINK_PENDING` to `LINK_UP`.                                                    | `link/handshake.test.ts`.                                        |
| 5     | Discovery produces `RemoteNodeHint`s; promotion guard passes.                                                  | `topology/promotion-guard.test.ts`.                              |
| 6     | Full pipeline produces a `CommittedRoute` with participant acceptance.                                         | `routing/full-pipeline.test.ts`.                                 |
| 7     | `CommittedRoute → ActiveCircuit`; AEAD framing, nonces, replay protection verified.                            | `circuit/full-pipeline.test.ts`, `circuit/replay.test.ts`.        |
| 8     | First end-to-end proof: HTTP(S) → ShareNet → relay(s) → gateway → real HTTPS server → response.              | `gateway/e2e-proof.test.ts`.                                     |
| 9     | Gateway session → signed receipt → `ContributionProof` → CivicPoints credit.                                  | `contribution/credit.test.ts`.                                   |
| 10    | Linux TUN adapter passes Phase 8 proof diagram on a single host.                                               | `platform/linux/e2e.test.ts`.                                    |
| 11    | Wallet → ShareNet → gateway → real network; custody never leaves the user.                                     | `bridge/custody.test.ts`, `bridge/e2e.test.ts`.                  |

## 5. Build-Stopping Failures

A conformance failure MUST stop the build. The CI configuration MUST
treat any failure of §2 or §3 tests as blocking. Phase exit conditions
in §4 are blocking for the corresponding phase's downstream work but
do not block unrelated work in earlier phases.

A test that is intentionally skipped (e.g., a Phase 10 test in a Phase
8 build) MUST be marked `it.skip` with a comment referencing the
phase, and MUST be re-enabled when the corresponding phase begins.
